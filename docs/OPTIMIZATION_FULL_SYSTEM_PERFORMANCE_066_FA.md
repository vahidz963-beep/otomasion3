# بهینه‌سازی کامل سرعت سیستم - کد + SQL 066

## انتخاب کاربر
بسته کامل پیشنهادی برای کل سیستم انتخاب شد:
- بهینه‌سازی کد
- بهینه‌سازی SQL / ایندکس‌ها
- بدون Deploy

## تغییرات کدی انجام‌شده

### 1. حسابداری
- لود اولیه حسابداری سریع‌تر شد؛ داده‌های اصلی اول نمایش داده می‌شوند.
- داده‌های سنگین مثل کاردکس، سود سفارش، حقوق، وام، هزینه/درآمد و ... در زمان بیکاری مرورگر و با تأخیر سبک لود می‌شوند.
- در به‌روزرسانی زنده، دیگر کل صفحه حسابداری با حالت loading دوباره قفل نمی‌شود.
- به‌روزرسانی زنده حسابداری سبک‌تر شد و لودهای سنگین پس‌زمینه در هر تغییر کوچک تکرار نمی‌شوند.
- حجم بعضی لیست‌های سنگین پس‌زمینه محدودتر شد تا فشار اولیه کمتر شود.
- یک query تکراری در صورت‌حساب اشخاص حذف شد.

### 2. سفارش‌ها
- به‌روزرسانی زنده سفارش‌ها سبک‌تر شد و بدون قفل‌کردن صفحه انجام می‌شود.
- تغییرات مشتریان و اشخاص حسابداری باعث refresh خودکار سفارش‌ها می‌شود، ولی بدون نمایش loading سنگین.

### 3. داشبورد
- گزارش سلامت سیستم از لود اصلی داشبورد جدا شد و در پس‌زمینه لود می‌شود.
- بنابراین داشبورد برای KPIها و نمودارها سریع‌تر باز می‌شود و منتظر گزارش سلامت نمی‌ماند.

## SQL جدید
فایل زیر اضافه شد:

`supabase/migrations/066_performance_full_system_indexes.sql`

این فایل ایندکس‌های امن و قابل اجرای چندباره برای بخش‌های زیر اضافه می‌کند:
- حسابداری و فاکتورها
- دریافت/پرداخت‌ها
- اسناد حسابداری و ردیف‌های سند
- اشخاص مالی
- مشتریان و CRM
- سفارش‌ها و مراحل سفارش
- ارجاعات
- انبار و کاردکس
- تولید
- R&D
- وام‌ها
- حقوق و دستمزد
- هزینه‌ها و درآمدها

در انتهای SQL نیز `ANALYZE` اجرا می‌شود تا PostgreSQL از ایندکس‌ها بهتر استفاده کند.

## ترتیب اجرای SQL
