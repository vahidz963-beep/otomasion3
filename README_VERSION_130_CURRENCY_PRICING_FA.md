# راهنمای انتشار نسخه ۱۳۰ — مرکز قیمت‌گذاری ارزی انبار

## قابلیت‌های این نسخه

- مرکز «قیمت‌گذاری دلاری و یوانی کالاها» در تب «همگام‌سازی انبارا»
- دریافت مستقل نرخ USD و CNY از سه منبع TGJU، الان‌چند و PriceToDay
- محاسبه میانه پاسخ‌های معتبر و پذیرش یک منبع معتبر در صورت قطع دو منبع دیگر
- بروزرسانی دستی احراز هویت‌شده و بروزرسانی خودکار روزانه ساعت ۰۸:۰۰ تهران
- ثبت ارز مبنا، بهای خرید پایه و قیمت فروش پایه هر کالا
- تبدیل گروهی ارز پایه USD/CNY با حفظ دقیق قیمت جاری ریالی/تومانی
- گردکردن قیمت جاری به نزدیک‌ترین ۱٬۰۰۰ تومان
- انتشار بهای خرید جاری به انبار، تولید، BOM و R&D و قیمت فروش جاری به انتخاب کالا در سفارش و مالی
- بروزرسانی خودکار هزینه متریال BOMهای فعال/پیش‌نویس پس از تغییر قیمت یا نرخ
- قیمت‌گذاری محصول تولیدی از هزینه BOM به‌علاوه درصد سود
- Snapshot دائمی قیمت، ارز و نرخ روی ردیف سفارش، پیش‌فاکتور و فاکتور
- تاریخچه حسابرسی نرخ‌ها و تغییر قیمت کالا
- حفظ قیمت ریالی کالاهای قدیمی تا زمان ثبت دستی قیمت ارزی
- واردات Excel/CSV فقط مشخصات و موجودی را همگام می‌کند و قیمت را بازنویسی نمی‌کند

## ترتیب امن انتشار

اگر نسخه ۱۲۹ هم‌اکنون روی سامانه فعال است:

1. از دیتابیس Supabase پشتیبان بگیرید.
2. فقط Migration زیر را در **Supabase SQL Editor** اجرا کنید:

   `supabase/migrations/122_warehouse_multi_currency_pricing.sql`

3. فایل‌های این بسته Flat را مستقیماً روی ریشه مخزن فعلی کپی کنید.
4. در GitHub Desktop گزینه‌های **Commit to main** و سپس **Push origin** را اجرا کنید.
5. در Netlify نتیجه Build و اجرای Functionها را بررسی کنید.

> Migration 119 را دوباره اجرا نکنید. اگر دیتابیس هنوز Migrationهای نسخه ۱۲۹ را ندارد، ابتدا Migrationهای جاافتاده را به ترتیب شماره اجرا کنید و سپس 122 را اجرا کنید.

## متغیرهای لازم در Netlify

این مقادیر باید در **Site configuration → Environment variables** موجود باشند:

```text
VITE_SUPABASE_URL=...
VITE_SUPABASE_ANON_KEY=...
SUPABASE_URL=...
SUPABASE_ANON_KEY=...
SUPABASE_SERVICE_ROLE_KEY=...
```

`SUPABASE_SERVICE_ROLE_KEY` فقط در Netlify Function مصرف می‌شود و نباید با پیشوند `VITE_` ثبت شود.

## زمان‌بندی نرخ

در `netlify.toml` تابع زیر ثبت شده است:

```toml
[functions."scheduled-exchange-rates"]
  schedule = "30 4 * * *"
```

این زمان برابر با ۰۴:۳۰ UTC و ۰۸:۰۰ تهران است.

## کنترل سریع پس از انتشار

1. با کاربر دارای نقش `admin` یا `warehouse` وارد شوید.
2. به «انبارداری → همگام‌سازی انبارا» بروید.
3. کارت‌های دلار و یوان، زمان آخرین نرخ و وضعیت سه منبع را بررسی کنید.
4. «به‌روزرسانی نرخ‌ها الآن» را بزنید؛ حداقل یک منبع معتبر برای هر ارز کافی است.
5. برای یک کالای عادی، ارز پایه و قیمت خرید/فروش را ثبت کنید.
6. برای یک محصول تولیدی، ابتدا BOM هزینه‌دار را از تولید به انبار منتشر و سپس درصد سود را در مرکز قیمت‌گذاری ثبت کنید.
7. یک سفارش یا پیش‌فاکتور آزمایشی بسازید و قیمت انتخاب‌شده را بررسی کنید.
8. نرخ را دوباره بروزرسانی کنید و تأیید کنید سند قبلی ثابت مانده ولی انتخاب جدید قیمت روز را می‌گیرد.
9. تبدیل گروهی به USD یا CNY را روی داده آزمایشی کنترل کنید؛ قیمت تومانی همان لحظه نباید تغییر کند.

## کنترل SQL اختیاری

```sql
select id, usd_toman, cny_toman, usd_status, cny_status,
       usd_source_count, cny_source_count, last_checked_at
from public.warehouse_exchange_rates;

select item_code, item_name_fa, price_currency,
       base_cost_price, base_sale_price,
       current_cost_rial, current_sale_rial, margin_pct,
       pricing_mode, has_currency_price
from public.v_warehouse_currency_prices
order by item_code;

select currency, applied_rial, source_count, decision_status, accepted, created_at
from public.warehouse_exchange_rate_history
order by created_at desc
limit 20;
```

## نکات داده‌ای

- هیچ قیمت قدیمی به‌زور تبدیل نمی‌شود؛ کالای ریالی تا ثبت قیمت ارزی، ریالی می‌ماند.
- قیمت اسناد ثبت‌شده با نرخ‌های بعدی بازنویسی نمی‌شود.
- حذف فیزیکی داده‌های مالی در این نسخه انجام نمی‌شود.
- نرخ و تغییر قیمت دارای تاریخچه حسابرسی هستند و گردش تأیید جداگانه ندارند.
